# ADR 0013 빌드 발견 후보와 검증 명세를 분리한다

날짜: 2026-11-14. 상태: **로컬 명세 검증 도구에 적용. 관측 backend·자동 생산기·영구 저장 방식은 미결**.

연결: [#78](https://github.com/DDINGJOO/JJAM-TONG/issues/78) → [#65](https://github.com/DDINGJOO/JJAM-TONG/issues/65), [요구사항](../requirements/BUILD-INVENTORY.md), [BDD](../../specs/features/14-build-inventory.feature).

## 문제와 대안

저장소마다 Maven·Gradle의 모듈 경로와 입력 구성이 다르다. 빌드 파일을 읽는 것만으로 실제 컴파일 입력과 산출물을 확정할 수 없으며, 읽기 전용 발견 권한을 빌드 스크립트 실행 권한으로 확대해서도 안 된다.

| 대안 | 이점 | 문제·부담 |
| --- | --- | --- |
| 빌드 파일을 파싱해 실제 구성을 추정 | 설치 부담이 적고 빠르게 후보를 제공 | 동적 설정·프로필·생성 소스 때문에 확정적 근거로 쓰기 어려움 |
| 발견 시 임의의 빌드를 자동 실행 | 평가된 입력을 얻을 가능성이 높음 | 별도 실행 권한·격리·의존성·네트워크·비용 정책이 필요 |
| 정적 발견 후보와 외부 생산 명세를 분리 | 이식 가능한 입력 계약과 정확한 산출물 선택을 먼저 검증 | 소유자가 실제 입력을 생산해야 하고 부분 수집을 설명해야 함 |

세 번째 대안을 이번 로컬 도구에 적용한다. 정적 발견 결과는 후보로 남기며, 명시한 명세의 파일 해시를 별도 검증한다. 검증한 기록은 덮어쓰지 않고 두 명세 해시를 고정해 비교한다. 명세의 선언 시각과 로컬 검사 시각은 서로 다른 필드다.

## 적용 범위와 영향

모듈 의존 관계의 차이와 이전·현재의 영향 경로를 비교한다. 이 결과를 실제 요청 실행이나 변경으로 인한 장애의 증명으로 표시하지 않는다. 수집되지 않은 정보, 해당 없는 입력, 명시적인 빈 집합도 구분한다.

표준 라이브러리로 구현하며 기존 분석의 다섯 빌드 필드와 해시 검사, PostgreSQL 스키마와 웹 조회 계약은 보존한다. Datadog·Elastic의 서비스 버전 연결을 참고하되 제품·DB를 채택하지 않는다. 파일 해시는 완전한 컴파일 입력이나 신뢰 가능한 소스→산출물 출처의 증명이 아니다.

후속으로 소유자가 실행할 빌드 명세 생산기, 명세 서명·출처, 분석 작업 예약과 실제 메서드 차이, 지속 저장·용량, 런타임과 과거 정답표를 검증한다. [ADR 0012](0012-evidence-identity-time-model.md)의 식별·시간 모델을 유지하며 [#79](https://github.com/DDINGJOO/JJAM-TONG/issues/79)의 과거 재생을 이 작업의 완료로 계산하지 않는다.
