# ADR 0003 — 실행 모델 비교를 위한 별도 검증 대상

날짜: 2026-11-12. 상태: **로컬 비교 실험의 경계 결정 / 제품 실행 모델·계측 도구는 미결**.

연결: [T25 #44](https://github.com/DDINGJOO/JJAM-TONG/issues/44), [추가 검증 조건](../experiments/CODE-ANALYSIS-COMPARISON.md#실행-모델과-이벤트-경계도-함께-검증한다).

## 문제와 결정

사용자가 요청한 Spring Boot 4의 가상 스레드·Netty·이벤트 통신 비교를 실제로 실행한다. HTTP 서버, 작업 실행기, Kafka 소비자에 같은 스레드 모델이 적용된다고 가정하지 않는다. 기존 게시판을 전환하는 대신 별도 대상 저장소에 작은 검증 모듈을 둔다. 같은 합성 처리와 기존 로컬 Kafka·Redis·PostgreSQL을 사용하고 테이블·토픽·소비자 그룹은 기존 게시판과 구분한다.

비교 대상은 MVC/Tomcat의 플랫폼 스레드, 같은 앱의 가상 스레드 설정, WebFlux/Netty와 별도로 제한한 블로킹 작업 실행기다. WebFlux starter는 이 비교 대상에만 추가한다. 이번 실행 승인과 이 ADR을 플랫폼의 WebFlux·OTel·분석기 채택으로 해석하지 않는다.

요청별 문맥을 명시적으로 전달하는 수동 검증 코드를 사용한다. 요청 진입·작업·outbox 발행·Kafka 처리를 구분해 실제 스레드와 빌드 식별을 기록한다. 문맥 누락은 미해결로 남긴다. 이 코드는 자동 메서드 계측이나 OTel Span Links 구현의 증거가 아니다.

## 대안과 선택 이유

| 대안 | 장점 | 비용·판단 |
| --- | --- | --- |
| 기존 게시판을 WebFlux로 전환 | 업무 흐름을 그대로 비교 | 기존 기준 구성을 바꾸고 이식성 실험에 앱 재작성 비용이 섞임 |
| 실제 서버·메시지 없이 모의 테스트만 수행 | 빠르게 문맥 계약 확인 | 이벤트루프·JDBC·실제 Kafka 처리 경계를 입증하지 못함 |
| 별도 모듈에서 같은 합성 처리 실행 | 기존 앱을 유지하며 실제 실행 경계를 비교 | 수동 검증 범위에 한정됨. 이번 실험으로 선택 |

## 판정과 후속

문맥의 유지·누락, 재처리와 중복 효과, 작업 상한·실패를 기대값과 대조한다. 응답 시간만으로 실행 모델의 우열을 정하지 않는다. JDK 21·25의 pinning은 동일한 클래스 파일과 JFR(Java Flight Recorder) 기록을 사용한 별도 입력으로 비교한다. 배포판도 다르므로 단일 변수 성능 실험으로 표현하지 않는다.

실제 실행 조건·결과와 미실행 항목은 [실행 모델 비교 기록](../experiments/EXECUTION-MODEL-RESULTS.md)에 남긴다. 제품 계측 도구의 선정, 자동 호출 그래프와 실행 기록의 결합, 전체 C01~C12 및 BDD 통과는 별도 작업으로 유지한다.
