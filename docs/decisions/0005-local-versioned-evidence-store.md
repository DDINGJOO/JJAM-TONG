# ADR 0005 — 버전별 메서드 근거의 첫 로컬 저장 경계

날짜: 2026-11-13. 상태: **첫 로컬 공통부에 PostgreSQL 적용 / 전체 플랫폼 스택은 미결**.

연결: [T25 #44](https://github.com/DDINGJOO/JJAM-TONG/issues/44), [T24 #43](https://github.com/DDINGJOO/JJAM-TONG/issues/43), [구현과 명령](../../tools/evidence_store/README.md), [실제 검증](../experiments/VERSIONED-EVIDENCE-STORE.md).

## 문제와 선택

분석 결과를 파일에만 보관하면 저장 책임과 그래프 조회의 교체 경계를 검증하기 어렵다. 한편 작은 조회에서 빨랐던 DB가 모든 플랫폼 데이터의 원본이 되어야 하는 것은 아니다. 사용자는 PostgreSQL부터 시작하고 그래프 조회 엔진의 교체 경계를 두자는 제안에 동의했다. 이번 선택은 **로컬 메서드 근거 저장 공통부**에 적용한다.

[네 엔진 비교](../experiments/STORAGE-ENGINE-COMPARISON.md), [단독·원본 책임별 16개 구성](../experiments/STORAGE-TOPOLOGY-COMPARISON.md), [규모별 그래프 비교](../experiments/GRAPH-SCALE-COMPARISON.md)를 근거로 삼는다. 넓은 순차 조회와 내부 메서드의 깊은 조회·짧은 동시 조회에서 유리한 엔진이 달랐다. 단일 호스트의 합성 실험은 보편적인 성능 순위나 운영 수용량을 정하지 않는다.

현재 Python 연동 도구에서 PostgreSQL 17.11과 이미 사용한 Psycopg 3.2.12를 재사용한다. Java 라이브러리의 배포 의존성에 DB 드라이버를 넣지 않는다. 전체 제품 언어·설치 환경·로그/집계 저장소와 메시지 중개 도구는 이번 결정에서 정하지 않는다.

## 저장과 조회의 책임을 나눈다

| 경계 | 책임 |
| --- | --- |
| `AnalysisRepository` | 조직 라벨·분석 실행 ID별 불변 색인의 발행과 정확한 해시 조회 |
| `GraphQueryPort` | 지정한 분석 해시·분석기·메서드·예산에 해당하는 정적 호출 후보 조회 |
| `EvidenceReader` | 원본 선택과 그래프 결과의 요청 일치 검사, 기존 trace 대조 기능 호출 |
| 첫 PostgreSQL 어댑터 | 원본 JSON과 분석기별 관계를 원자적으로 저장하고 두 계약을 구현 |

색인은 버전별 메서드 분석 결과를 담은 JSON 문서다. 조회용 관계에는 같은 색인의 해시를 붙인다. 해시가 다른 원본과 조회 결과는 결합하지 않는다. 같은 ID·해시의 재시도는 허용하고, 같은 ID에 다른 내용을 발행하면 충돌로 거부한다. 이 계약은 기존 파일 저장 경로의 중복 거부 동작과 구분한다.

현재 원본·조회용 관계는 한 트랜잭션에 저장하므로 비동기 동기화 지연은 없다. 이후 엔진을 나누면 해당 분석 해시의 준비 완료를 확인하는 경계를 추가하고 중단·지연·재구축을 실제 검증해야 한다. 인터페이스를 나눴다는 이유로 복제나 교체 구현이 끝난 것으로 보지 않는다. Neo4j를 그래프 원본으로 선택하는 대안도 열려 있으며, 그때는 조회 계약뿐 아니라 저장 계약의 구현·이관을 검증한다.

## 대안과 부담

| 대안 | 이번 범위의 판단 |
| --- | --- |
| 파일만 유지 | 기존 실험은 그대로 보존. 동시 발행·원자적 관계 공개를 검증하는 새 저장 경로를 추가 |
| PostgreSQL 하나로 모든 영역 확정 | 이번에 채택하지 않음. 로그 검색·시계열 집계·보안 데이터는 질문과 비용으로 별도 판단 |
| Neo4j부터 시작하거나 PostgreSQL과 즉시 병용 | 깊은 관계 탐색의 장점은 실측. 첫 저장 공통부에는 추가 운영·동기화 책임을 넣지 않음 |
| Elasticsearch / ClickHouse 원본과 조합 | 구성 비교의 대안으로 보존. 현재 공통부의 불변 발행·재시도 계약과 각 영역 요구를 기준으로 재평가 |

첫 구현은 10 MiB 이하의 기존 Java 색인 형식에 맞췄다. 모든 언어의 공통 메서드 형식이나 대형 분석 결과의 수용량을 확정하지 않는다. 조직 라벨은 데이터 선택 조건이며 기업 인증·인가·행 수준 격리는 남아 있다. 정적 후보와 실제 span 관계, 선언·구현 후보, 미해결·부분 결과는 각각 보존한다.

## 검증과 후속

독립 합성 계약 시험과 실제 PostgreSQL 시험에서 충돌·롤백·이력 조회·버전 분리·조회 상한을 검증했다. 별도 대상에서 이미 만든 두 Java 빌드의 분석·실행 기록도 다시 조회했다. DB 재시작 후 같은 기록의 조회 결과를 확인했다. 구체적인 실행 결과는 [검증 문서](../experiments/VERSIONED-EVIDENCE-STORE.md)에 둔다.

운영 보존·삭제·마이그레이션, 인증·인가·감사, 다중 노드 복구·고가용성, 지속 수용량·자동 확장은 앞으로 검증한다. #44의 정확한 overload 실행 식별·실제 부분 재분석·이벤트 문맥·수집 유실 조건을 이 저장 검증으로 완료 처리하지 않는다.

트랜잭션·동시성의 구현 근거는 [PostgreSQL 17의 격리 수준](https://www.postgresql.org/docs/17/transaction-iso.html), [충돌 시 INSERT 동작](https://www.postgresql.org/docs/17/sql-insert.html), [Psycopg의 트랜잭션 문맥](https://www.psycopg.org/psycopg3/docs/basic/transactions.html)이다. 실제 고정 버전에서 수행한 통합 시험과 함께 판단한다.
