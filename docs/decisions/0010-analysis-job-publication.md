# ADR 0010 분석 작업의 완료 증거와 결과 발행 비교

- 상태: 로컬 공통 계약·비교 실험에 적용. 플랫폼 전송 규격·인프라 채택과 기존 생산자·소비자 전환은 미결이다.
- 날짜: 2026-11-14
- 작업: [#64](https://github.com/DDINGJOO/JJAM-TONG/issues/64), 상위 [#44](https://github.com/DDINGJOO/JJAM-TONG/issues/44), 선행 [ADR 0009](0009-java-parser-retention.md)

## 문제와 판단 기준

기존 Java 분석기는 401,023줄 합성 입력에서 10 MiB 출력 상한으로 실패했다. 직렬화 이후 검사하므로 파일 상한이 직렬화 중 메모리를 제한하지는 않는다. 입력·시도·실패·완료를 구분하지 않은 채 저장 크기만 바꾸면 일부 결과나 이전 빌드를 성공으로 발행할 수 있다.

판단 기준은 정확한 입력·버전 연결, 부분 실패와 완료의 구분, 강제할 수 있는 예산의 명시, 기존 소비자의 변경 비용이다. [공통 계약](../requirements/ANALYSIS-JOB.md)과 [같은 합성 레코드의 비교 결과](../experiments/ANALYSIS-JOB-CONTRACT.md)를 사용한다.

## 대안

| 대안 | 이점 | 비용·한계 |
| --- | --- | --- |
| 직렬화 중 제한하는 단일 파일 | 형식·읽기 경로가 단순하고 큰 전체 문자열을 만들 필요가 없다 | 파일당 상한을 넘는 결과는 여전히 실패한다. 레코드·인코더 조각과 분석기 메모리는 별도다 |
| 단일 파일의 상한 변경 | 하나의 완료 파일과 기존에 가까운 조회 흐름을 유지할 수 있다 | 생산자·전송·소비자·DB의 상한과 수신 비용을 함께 바꾸고 검증해야 한다 |
| 불변 조각과 완료 명세 | 파일당 상한을 유지하며 더 큰 논리 결과를 표현하고 누락·손상·버전 혼입을 검증할 수 있다 | 명세·조각 수·전체 크기·실패 조각 정리·원자적 수신과 전환 규격이 필요하다 |
| 압축 표현 | 데이터의 중복도에 따라 전송·저장량을 줄일 수 있다 | 이번에 실행하지 않았다. 압축 전·후 및 복원 크기 상한·CPU·호환 계약을 별도 비교해야 한다 |

## 결정

로컬 실험에는 입력 키·실행 시도·단계·완료 증거를 분리하는 계약을 적용한다. `Job.finish`는 raw JSON 명세를 받지 않고 모든 조각 검증을 마친 `VerifiedCompletion`을 받는다. 이는 신뢰하는 프로세스 안의 API 오용 방지이며 출처 인증이나 악의적인 Python 코드의 격리 수단은 아니다.

단일 파일과 분할 결과 모두 전체 발행 바이트에 완료 메타데이터를 포함한다. 파일당·전체·레코드·조각·명세·조각 수의 상한을 구분하고 수신 때도 검사한다. 일부 조각의 존재나 같은 모양의 명세만으로 완료를 만들지 않는다.

파일당 10 MiB 제한을 유지하면서 더 큰 결과를 다룰 때의 후속 후보는 분할 방식이다. 단일 파일 상한을 바꿀 수 있는 경우에는 그 대안도 유지한다. 실험에서 두 형식은 같은 논리 레코드와 전체 예산으로 비교했지만 레코드별 포장 비용과 실제 바이트 수는 다르다. 단일 표본으로 속도·메모리의 보편적 우위를 정하지 않는다.

## 검토에서 바꾼 내용

첫 독립 코드 검토에서 완료 증거 타입 부재, 명세를 제외한 전체 바이트 집계, 비교 작업의 시간 초과 기록 누락을 지적했다. 각각 타입으로 구분한 검증 결과·명세 포함 상한·시도별 시간 초과 기록과 회귀 검사로 보완한다. 시간 초과 시 완료 파일이 보였더라도 검증하지 못한 결과를 성공으로 인정하지 않는다. 독립 재검 결과는 #64와 PR에 남긴다.

## 영향과 후속

기존 Java v1·수집기·메서드 색인·DB·화면을 이 ADR만으로 전환하지 않는다. 실제 40만 줄 입력·소비자 상한·버전 혼입·저장·화면 QA는 [#68](https://github.com/DDINGJOO/JJAM-TONG/issues/68)에서 검증한다. 실패 조각의 보존·정리, 원격 저장소의 내구성·분산 소유권·OS 자원 강제는 [#37](https://github.com/DDINGJOO/JJAM-TONG/issues/37)의 실행 경계와 함께 구체화한다. 빌드·모듈 발견과 서비스 간 관계의 근거 계약은 #65·#66으로 이어간다.
