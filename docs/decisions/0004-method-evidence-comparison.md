# ADR 0004 — 정적 메서드 후보와 실행 근거의 로컬 비교

날짜: 2026-11-12. 상태: **비교 실험 구현 / 제품 분석기·계측 스택은 미결**.

연결: [T25 #44](https://github.com/DDINGJOO/JJAM-TONG/issues/44), [비교 조건](../experiments/CODE-ANALYSIS-COMPARISON.md), [실제 결과](../experiments/METHOD-OBSERVABILITY-RESULTS.md).

## 문제와 선택 범위

사용자는 자동 메서드 계측까지 이어가는 제안에 “ㅇㅇ 다해줘 진행~”으로 비교 실행을 승인했다. 이에 따라 이미 우선 비교안으로 제시한 **JavaParser·SymbolSolver 3.28.2, WALA 1.9.0, OpenTelemetry Java agent 2.33.1**을 로컬 합성 입력에 적용한다. 이 승인은 이번 비교에 한정하며 제품 채택이나 전체 아키텍처 결정으로 확대하지 않는다.

JavaParser는 소스가 참조한 선언을 해석한다. WALA는 클래스 계층 분석(CHA)으로 지정한 진입점에서 가능한 호출 후보를 계산한다. 두 근거를 별도 항목으로 보관한다. OTel은 agent 없음·기본 계측·선택 메서드 계측으로 나눠 실제 실행과 대조한다. 대상 앱은 별도 로컬 저장소에 두고 플랫폼에는 연동 도구와 작은 독립 검사만 둔다.

WALA는 Maven Central에 배포된 바이너리로 실행한다. WALA 자체 소스 빌드가 요구하는 JDK 27을 새로 설치하지 않는다. 어댑터는 Java 17 클래스 형식의 일반 JAR과 JDK 17·21 실행을 검증 범위로 제한한다. 플랫폼의 다른 언어·환경 지원을 이 형식으로 고정하지 않는다.

WALA가 실행 의존성으로 사용하는 Gson 2.14.0을 JSON 입출력에 재사용한다. 직접 바이너리·공식 원문·라이선스 해시와 전체 해석 의존성 해시를 남긴다. JavaParser의 Apache-2.0 선택지와 WALA의 EPL-2.0 표기를 확인했으며, 전이 의존성 전체의 법률·보안 검토나 플랫폼 라이선스 결정은 별도다. [원문 근거](../../tools/java-call-analysis/dependency-provenance.json).

## 연결 계약과 보류한 대안

저장소·revision·build·module·최종 JAR 해시가 모두 맞을 때만 지정한 분석 실행에 연결한다. 설정이 다른 재분석은 새 ID와 색인으로 남기고, 수집하지 않은 과거를 최신 그래프로 채우지 않는다. manifest와 실제 로컬 파일은 대조하되 빌드 출처 인증으로 표현하지 않는다.

OTel의 선택 계측은 메서드 이름을 기준으로 하며 JVM descriptor를 내보내지 않는다. 선택한 색인에서 같은 클래스·메서드 이름의 선언 후보가 하나일 때만 그 후보의 descriptor를 유도한다. 여러 후보가 있으면 미해결로 반환한다. 인터페이스와 구현체를 동시에 선택하면 한 본문에 계측이 중복될 수 있어 이번 입력은 구체 클래스의 본문만 선택한다. 수집한 span의 부모 관계를 정적 동기 호출로 바꾸지 않는다.

Byte Buddy 자체 계측은 descriptor 수집 등 미해결 요구를 비교할 대안으로 남긴다. 아직 구현하거나 직접 의존성으로 추가하지 않았다. SootUp·AppMap·SkyWalking 등 기존 후보를 제외하는 결정도 아니다. 실제 부분 영향 범위 계산이 없으면 전체 재분석으로 전환하며, 같은 전체 결과를 선택했다는 이유로 증분 분석 성능을 입증했다고 주장하지 않는다.

## 검증과 후속

[124개 기능 실행·30회 비용 측정·이력 반례](../experiments/METHOD-OBSERVABILITY-RESULTS.md)를 기록한다. 정적 overload 구분과 실제 overload 식별 실패를 함께 남긴다. 원시 시간의 0ns 값도 보존하며 매우 짧은 기준 입력의 성능 비율 판정은 보류한다.

별도 Boot·가상 스레드·Netty 앱에도 agent를 적용했다. `00`·`01` 이외의 trace 플래그를 거부하던 합성 대상 파서를 수정하고, 새 빌드로 3개 기능 흐름을 검증했다. HTTP→예약 outbox의 SDK 추적 단절과 Redis 전용 span 미관측은 해결한 것으로 처리하지 않는다. 이 결과는 순수 Java의 정적 색인 연결·비용 행렬과 별도 근거다.

이 실험의 근거 연결 도구는 전체 Java 지원, 운영 수집기, 자동 온보딩·지속 갱신 서버 또는 통합 플랫폼의 완료가 아니다. 정확한 overload 계측, 실제 부분 재분석, 이벤트 경계 문맥 보존과 전송 유실 검증을 T25의 남은 조건으로 관리한다.
