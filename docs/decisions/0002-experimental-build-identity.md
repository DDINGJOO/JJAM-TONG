# ADR 0002 — 로컬 검증용 빌드 식별 계약

날짜: 2026-11-12. 상태: **외부 의존성 없는 Java 실험 계약 채택 / 제품 규격·분석기·계측 방식 미결**.

연결: [T25 #44](https://github.com/DDINGJOO/JJAM-TONG/issues/44), [버전 BDD 초안](../../specs/features/02-version-identity.feature), [라이브러리와 실행 방법](../../libraries/evidence-contract-java/README.md).

## 문제와 결정 기준

같은 커밋이나 버전 문자열로 만든 앱도 의존성·빌드 조건·산출물이 다를 수 있다. 실행 기록을 최신 코드 지도에 붙이는 대체 동작을 막기 위해 빌드 식별 정보를 먼저 비교한다. 대상 앱과 라이브러리를 분리하고, 분석·계측 도구를 정하기 전에 검증 가능한 작은 공통부를 만든다.

## 결정

`BuildIdentity`는 저장소·revision·빌드·모듈·최종 산출물 SHA-256을 구분한다. `AnalysisIdentity`는 대상 빌드에 분석 실행·분석기 이름/버전·스키마 버전·설정/인덱스 SHA-256을 추가한다. 해시는 64자리 16진수를 소문자로 정규화하고, 다른 식별자는 빈 값을 거부하며 입력 문자열 그대로 비교한다. 공급원별 형식 검증은 이후 연동 도구의 책임이다.

호출자가 선택한 분석과 실행 측 식별 정보가 모두 있으면 다섯 빌드 필드를 비교한다. 모두 같으면 `MATCH`, 다르면 `MISMATCH`와 다른 필드 이름을 반환한다. 어느 한쪽이 없으면 `UNRESOLVED`로 남기고 최신 지도나 추측한 식별자를 대입하지 않는다. 같은 빌드의 다른 분석 실행·설정은 별개로 보존한다.

`MATCH`는 **제공된 메타데이터의 일치**만 의미한다. 실제 실행, 출처의 진위, 요청·메서드 관계, 분석 스키마의 호환성까지 입증하지 않는다. 불완전한 정보를 `unknown` 같은 문자열로 채우지 않는 것은 호출자의 책임이다. 최종 산출물 해시는 패키징 후 앱 JAR 밖의 별도 메타데이터 파일(sidecar manifest)에 기록한다. 파일 전체의 해시를 그 파일 안에 넣는 순환을 피한다.

## 대안과 선택 이유

| 대안 | 이점 | 비용·판단 |
| --- | --- | --- |
| 커밋·앱 버전 문자열만 비교 | 전달할 정보가 적음 | 같은 커밋의 다른 산출물을 구분하지 못하므로 제외 |
| 분석·계측 프레임워크에 계약을 먼저 결합 | 실제 호출 관측을 빠르게 시도할 수 있음 | 도구·agent 선택이 미결이며 공통 식별 계약을 특정 도구에 묶게 됨 |
| 의존성 없는 작은 Java 계약 | 실제 JAR을 외부 앱이 소비하고 버전 오연결 반례를 먼저 검증 | 자동 계측 결과는 아직 제공하지 못함. 이번 실험 범위로 선택 |

이번 선택은 Java 17 클래스 파일과 Java API에 한정한다. 플랫폼 전체의 언어·빌드 도구·저장소·메시지 중개 도구를 확정하지 않는다. 호스트에 새 패키지를 설치하지 않고 JDK 도구와 Python 표준 라이브러리로 빌드한다.

## 확인한 결과와 후속

[실행 기록](../experiments/library-contract-results.json)에서 JDK 17·21의 각 23개 검증과 JDK 17 JAR의 JDK 21 소비 검증을 확인한다. 일치하는 입력, 다섯 필드 각각의 불일치, 같은 커밋의 다른 산출물, 누락, 다른 분석 설정, 잘못된 해시, 실제 파일 해시를 검사했다.

별도 MSA 대상에도 이 JAR을 적용하고 [장애·복구를 포함한 9개 로컬 시나리오](../experiments/LOCAL-MSA-TARGET.md)를 실행했다. 다음은 정적 분석기와 런타임 계측 방식을 선택해 C01~C12를 실행하는 것이다. 이 계약만으로 메서드 분석·trace 수집이나 기존 BDD가 완료되지는 않는다. 분석 시점·신선도·권한·보존·미지원 상태·언어 간 직렬화 계약도 남아 있다.
