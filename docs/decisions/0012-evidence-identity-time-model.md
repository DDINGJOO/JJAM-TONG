# ADR 0012 근거의 식별자와 시간 모델 검증

날짜: 2026-11-14. 상태: **작은 논리 계약 실험에 적용. 전체 플랫폼의 물리 스키마·저장 엔진은 미결**.

연결: [#76](https://github.com/DDINGJOO/JJAM-TONG/issues/76) → [#65](https://github.com/DDINGJOO/JJAM-TONG/issues/65), [논리 모델](../requirements/EVIDENCE-MODEL.md), [BDD](../../specs/features/13-evidence-model.feature).

## 문제와 판단 기준

현재 PostgreSQL의 세 테이블은 분석 원본과 분석기별 정적 관계를 보관한다. 플랫폼 전체를 연결하려면 모듈·서비스·빌드·배포·자원의 식별과 시간 기준을 먼저 구체화해야 한다. 같은 커밋의 다른 산출물, 롤링 배포와 늦은 수집에서 다른 근거를 합치면 분석 결과를 신뢰할 수 없다.

판단 기준은 정확한 버전·시점 연결, 공급원·언어의 이식성, 기존 분석 소비자와 호환되는 작은 검증 범위다. 해시 일치를 신뢰할 수 있는 빌드 출처의 증명으로 해석하지 않는다.

## 대안과 선택

| 대안 | 이점 | 이번 단계의 부담 |
| --- | --- | --- |
| 현재 PostgreSQL을 타입별 도메인 테이블로 즉시 확장 | 기존 트랜잭션과 조회 경로를 활용 | 관계·시간 계약이 바뀌면 스키마와 소비자를 함께 이관해야 함 |
| 타입·식별·시간 계약을 작은 독립 실험으로 검증 | 오연결 반례를 DB와 별도로 검증하고 기존 경로를 보존 | 실제 저장·조회 성능을 입증하지 않으며 연결부가 필요 |
| PostgreSQL 원본과 타입을 검사하는 그래프 조회 모델을 즉시 병용 | 관계 탐색을 원본 보관과 독립적으로 발전 | 두 저장 경로의 해시 일치·준비 상태·재구축 책임이 먼저 생김 |

두 번째 대안을 이번 하위 작업에 적용한다. 새 의존성을 추가하거나 PostgreSQL 스키마를 변경하지 않는다. 다른 대안도 실제 도메인·조회 요구와 운영 비용을 검증한 뒤 선택할 수 있다. 대상·속성·값을 행으로 저장하는 범용 EAV 모델은 타입·버전의 구분을 강제하기 어려워 이번 실험에서 제외한다.

## 적용 계약

대상의 안정적인 식별, 버전이 고정된 대상, 출처를 가진 관계 주장을 구분한다. 관계는 허용한 대상 종류와 근거 종류를 검사한다. 유효 시간과 플랫폼이 알게 된 시간을 함께 조회하고 정정·철회는 추가 기록으로 보존한다. 다른 출처의 주장을 자동으로 덮어쓰거나 원본 자원 식별자를 병합하지 않는다.

기존 v1 연결부는 현재의 엄격한 입력 검사와 다섯 빌드 필드, 분석 실행·원본·설정 해시를 보존한다. 제공되지 않은 서비스·배포·런타임 정보를 생성하지 않는다. 이 연결부는 분석 메타데이터에 한정하며 기존 메서드 그래프·Trace 저장을 이관하지 않는다.

## 영향과 후속 검증

이 실험의 타입·시간·허용 참조 필터는 운영용 스키마나 기업 인증·인가 구현이 아니다. 작은 합성 결과와 실제 저장소에서 읽은 합성 분석을 [검증 결과](../experiments/EVIDENCE-MODEL-RESULTS.md)에 구분한다. 기존 PostgreSQL과 웹 소비자의 호환성을 회귀 검사한다.

다음 단계에서 #65의 빌드·모듈 명세를 이 계약으로 연결한다. 최종 저장 방식, 영구 ID 발급, 관계의 정정·우선순위 정책, 실제 공급원 시계·유실·보존, 다중 노드·지속 수용량을 별도로 검증한다. [ADR 0005](0005-local-versioned-evidence-store.md)의 첫 로컬 저장 결정은 유지한다.
