# 대규모 레거시 코드 분석 요구

정리된 예제뿐 아니라 공통 모듈에 업무 코드가 몰리고 여러 구조가 공존하는 프로젝트에서도 유용한 근거를 제공해야 한다. 분석을 위해 대상 프로젝트의 구조 개선을 먼저 요구하지 않는다. 다만 지원 입력과 자원 상한을 넘어선 경우에는 원인과 빠진 범위를 알려야 한다.

## 구조별 검증

| 구조 | 기대 결과 | 현재 확인 또는 다음 검증 |
| --- | --- | --- |
| 공통 모듈에 집중된 코드와 여러 진입 서비스 | 배포 입력·공유 코드·분석 단위를 구분하고 변경 영향을 전파한다 | 입력 전체 재사용만 구현했다. 실제 다중 모듈 클래스패스와 영향 전파를 다음에 검증한다 |
| 계층을 넘는 직접 호출과 순환 관계 | 기존 구조를 그대로 색인하고 순환을 숨기지 않는다 | 합성 순환 호출의 양방향 후보를 대조한다. 순환 묶음의 요약·확장 화면은 후속 범위다 |
| 인터페이스·상속·여러 구현체·오버로드 | 선언 대상과 실행 가능 후보를 구분하고 시그니처를 보존한다 | 선언 대상·두 구현체 후보·정확한 정적 descriptor를 실제 분석기로 대조한다. 실제 span의 overload 식별은 기존 미해결 과제다 |
| 생성 코드·브리지 메서드·Lombok·QueryDSL | 생성 입력과 바이트코드의 버전을 보존하고 소스 선언과 구분한다 | 합성 generic 구현과 컴파일러 생성 바이트코드를 포함한다. 실제 Lombok·QueryDSL 처리기 통합은 다음 검증 대상이다 |
| Spring DI·프로필·트랜잭션·프록시 | 설정에 따른 후보와 실제 관측을 구분한다 | 기존 Boot 가상 시작점은 실행 조건을 확정하지 않는다. 컨테이너·프레임워크별 해석을 추가 검증한다 |
| 람다·메서드 참조·리플렉션 | 해석한 관계와 해석하지 못한 관계를 함께 반환한다 | 합성 입력에서 JavaParser의 해석 공백과 임의 리플렉션 연결 부재를 확인한다 |
| 이벤트·스케줄러·스레드 전환·메시지 | 정적 후보·발행과 소비·실제 실행 문맥을 구분한다 | 기존 실행 모델 실험과 연결하되 해당 구조 전체의 정적 해석을 완료했다고 판단하지 않는다 |
| 불완전한 빌드·누락된 의존성·미지원 문법 | 지원 실패나 부분 범위를 명시한다 | 실패를 빈 성공 그래프로 바꾸거나 이전 빌드 결과로 대체하지 않는다 |

## 규모와 정확성의 판정

후속 파이프라인은 선언 색인과 호출 후보 계산을 분리하는 방안을 비교한다. 선언 색인이 먼저 준비되면 탐색을 제공하되, 호출 그래프가 실패하거나 아직 계산 중이면 해당 범위는 부분 완료로 표시한다. 빌드의 클래스패스·생성 입력을 확보하고 분석 결과를 나누어 저장한 뒤, 그 빌드의 명세에서 정확한 조각들을 참조하도록 설계한다. 현재 CLI는 두 분석기의 완전한 결과만 발행하며 이 단계별 발행은 아직 구현하지 않았다.

물리적 줄 수, 파일·선언·바이트코드 메서드·관계 수, 의존 JAR, 최대 호출 후보 수를 함께 기록한다. 줄 수가 같아도 계층·다형성·생성 코드의 밀도가 다르면 비용은 달라진다. 합성 산술 메서드 30만 줄의 결과를 실제 30만 줄 프로젝트의 수용량으로 일반화하지 않는다.

확정된 선언, CHA 호출 후보, 실제 관측, 미해결, 부분 수집, 빌드 불일치를 구분한다. 후보 수가 많다는 이유로 실제 호출을 확정하거나, 관측되지 않았다는 이유로 호출 불가능하다고 판단하면 실패다. 새 빌드에서 삭제된 메서드와 관계는 제거하되 과거 빌드의 이력은 보존한다.

새 증분 방식은 같은 소스·원본 산출물·설정의 전체 분석과 독립 대조한다. 구현체 추가·삭제, 상속 변화, 공유 라이브러리 변경, 생성 입력·프로필 변경, API 삭제, 동시 갱신·시간 초과를 포함한다. 일부 단위의 성공을 전체 빌드 성공으로 합산하지 않는다.

화면에서는 서비스·API·빌드에서 범위를 좁히고 필요한 메서드 주변만 확장하도록 설계한다. 순환 묶음·높은 연결 수·누락 범위와 결과 수 상한을 표시하고 특정 Trace의 실제 호출과 정적 후보를 구분한다. 확대 수준과 화면 크기에 따른 정보량 조절은 실제 규모 데이터로 별도 QA한다.
