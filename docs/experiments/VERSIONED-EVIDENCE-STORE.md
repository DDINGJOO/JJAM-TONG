# 버전별 메서드 근거 저장 공통부의 로컬 검증

날짜: 2026-11-13. 범위: **첫 로컬 저장·조회 경계 구현과 정확성 시험**.

[ADR 0005](../decisions/0005-local-versioned-evidence-store.md)에 따라 PostgreSQL을 첫 저장 어댑터로 연결했다. 원본 색인을 보관하는 계약과 그래프를 조회하는 계약을 분리했다. [구현·재현 명령](../../tools/evidence_store/README.md), [두 Java 빌드의 재조회 결과](versioned-evidence-store-replay.json), [T25 #44](https://github.com/DDINGJOO/JJAM-TONG/issues/44)를 연결한다.

## 확인할 문제와 실제 결과

| 시나리오 | 검증한 결과 | 근거 |
| --- | --- | --- |
| 같은 분석 ID에 같은 내용을 재전송한다 | 최초 발행만 생성하고 이후 `created: false` | 순차·동시 발행 시험 |
| 같은 ID에 다른 빌드를 동시에 발행한다 | 한 발행자만 성공하고 다른 발행자는 충돌; 덮어쓰기 없음 | 실제 PostgreSQL 동시 발행 시험 |
| 원본과 그래프 저장 사이에 실패한다 | 원본·메서드·호출 관계 모두 롤백; 재시도 가능 | 관계 저장 후 예외를 넣은 시험 |
| 다른 조직 라벨·분석 해시를 조회한다 | 라벨별 데이터 선택과 해시 불일치 거부 | 실제 PostgreSQL 시험; 인증·인가 시험은 아님 |
| 목록 밖 메서드·미해결·제외 항목이 있다 | 가짜 노드를 만들지 않고 원본·집계와 `PARTIAL`을 보존 | 계약·그래프 시험 |
| 순환 호출이나 넓고 깊은 관계를 조회한다 | 순환은 종료하고 깊이·노드·호출 상한을 드러냄 | 합성 그래프 시험 |
| 그래프 SQL이 시간 초과된다 | 탐색 중에는 `PARTIAL`·`TIME_BUDGET`; 시작 메서드 확인 전에는 `UNRESOLVED` | 실제 `pg_sleep` 문장 취소와 경계 모의 시험 |
| 색인에 허용하지 않은 본문·토큰 필드가 섞인다 | DB 발행 전에 거부; CLI 오류에 입력 본문을 출력하지 않음 | 중첩 필드·소스 본문·CLI 시험 |
| 기존 Java 분석 두 빌드를 다시 조회한다 | 두 빌드 × 두 분석기의 도달 메서드 집합이 원본 관계의 독립 탐색과 일치 | 원시 결과의 `graphChecks` 4개 |
| 이전 빌드의 실제 trace를 각각 연결한다 | 이전 빌드에서는 `OBSERVED`, 새 빌드에서는 `MISMATCH` | 원시 결과의 `traceStatuses` |

시험은 **새 계약 9개·PostgreSQL 경로 17개·기존 trace 연결 회귀 12개, 총 38개**가 통과했다. PostgreSQL 경로 중 일부는 SQL 외 경계 모의·CLI 검사를 포함한다. 탐색 중과 소비자의 선행 색인 조회에서 발생하는 시간 초과 시험은 실제 DB의 `pg_sleep(0.1)`과 10ms 제한을 사용했다. 원본·관계 저장을 한 트랜잭션에 묶고, 관계 조회는 한 시점의 DB 상태를 읽도록 했다.

PostgreSQL 컨테이너를 재시작한 후에도 같은 두 분석을 다시 읽었다. 공개 원시 결과는 재시작 후 최종 코드에서 실행한 결과이며 두 `publications.created` 값이 모두 `false`다. 같은 색인이 이미 저장되어 있었고 동일 재시도가 원본을 변경하지 않았음을 나타낸다. 재시작 수행 자체는 로컬 명령 기록으로 확인했으며 이 JSON만으로 재시작을 증명하지는 않는다.

## 입력과 실행 조건

PostgreSQL 17.11, Psycopg 3.2.12, Python 3.9를 사용했다. 전용 Compose 프로젝트의 CPU는 1개·메모리는 1 GiB이며 루프백 포트 29632만 열었다. 기존 컨테이너 11개와 별도 대상 앱의 소스는 변경하지 않았다. 시험 후 이 프로젝트의 컨테이너·네트워크를 정리하고 데이터 볼륨은 보존했다.

재조회 입력은 [기존 Java 메서드 실험](METHOD-OBSERVABILITY-RESULTS.md)의 `method-a1-jdk17`·`method-b1-jdk17` 색인과 이전 빌드의 선택 계측 기록이다. 원본 해시·현재 구현 파일 해시·서버 버전은 공개 JSON에 남겼다. 이번에는 JVM이나 업무 요청을 새로 실행하지 않았다. 합성 단위 시험의 호출 기록을 실제 trace라고 표현하지 않는다.

해당 보존 입력이 있을 때 아래와 같이 재현한다. 일반 저장·조회와 전체 시험은 [도구 README](../../tools/evidence_store/README.md)의 명령을 사용한다.

```sh
"$PYTHON" -m tools.evidence_store.verify_local \
  --index-a "$OLD_INDEX_JSON" --index-b "$NEW_INDEX_JSON" \
  --log "$OLD_OTLP_LOG" --telemetry-config "$OLD_TELEMETRY_CONFIG_SHA256" \
  --tenant local-replay --output .local/evidence-store-replay.json
```

이 재조회 명령은 기존 `fixture.board.Service.list` 합성 입력에 한정된다. 원본 자료를 가진 경로는 환경마다 다르며 공개 저장소에 대상 앱 소스·원시 실행 로그를 추가하지 않는다. 새 입력을 만들려면 기존 실험의 빌드·분석·색인 생성 과정을 먼저 수행한다.

## 요구사항에 연결하고 완료 범위를 구분한다

BDD-VER-001~003의 분석 식별·다른 빌드 분리·최신 그래프 대체 금지와 BDD-REL-003의 공백 표시에 검증 근거를 추가했다. 전체 BDD는 실행기 없는 요구사항 초안이며 이번 Python 시험이 모든 시나리오의 합격을 뜻하지 않는다. BDD-ENT-001의 조직 격리는 인증·인가를 포함하므로 조직 라벨별 SQL 시험만으로 충족하지 않는다.

그래프 조회는 나가는 호출 후보를 단계별로 찾는다. 모든 경로, 역방향 영향 분석, 도달한 노드 사이의 모든 관계를 열거하지 않는다. 미해결·제외 집계는 분석 전체의 범위이며 특정 시작 메서드가 그 공백을 만났다고 단정하지 않는다. 정적 후보와 실제 span 부모 관계는 서로 바꾸지 않는다.

스키마 허용 목록은 저장할 메타데이터 필드를 제한한다. **정상 필드에 숨긴 민감정보를 탐지하는 기능은 없다.** 신뢰하는 생산자가 만든 기술 메타데이터·합성 입력만 사용한다. 해시·로컬 입력 대조는 원격 빌드 출처 인증을 대신하지 않는다.

## 앞으로 검증할 항목

Neo4j 실제 어댑터와 조회용 데이터의 지연·재구축, 원본 책임 변경 시 이관, 실제 대형 코드의 지속 수용량, 보존·삭제·스키마 마이그레이션을 검증한다. 기업 인증·인가·감사, 고가용성·재해복구와 자동 확장도 별도 검증 대상이다. 기존 그래프 규모 비교의 수치가 이번 저장 공통부의 수용량 측정값이 되지는 않는다.

#44의 정확한 overload 실행 식별·부분 재분석·outbox SDK 문맥·Redis 관측 공백·실제 전송 유실 검증은 그대로 남아 있다. 기존 이슈의 열린 상태와 완료 조건을 유지한다.
