# 실제 메서드 근거를 확인하는 로컬 화면

저장한 분석 결과를 눈으로 확인할 수 있도록 기존 PostgreSQL 조회 계약에 로컬 HTTP API(웹 요청·응답 인터페이스)와 웹 화면을 연결했다. 사용자는 분석본의 정적 호출 후보와, 파일에서 읽은 실제 Trace(요청 하나의 실행 구간 묶음)를 각각 확인한다. 작업 이슈는 [T25 #44](https://github.com/DDINGJOO/JJAM-TONG/issues/44)이며, 실제 Boot 입력은 [앞선 검증](BOOT-METHOD-EVIDENCE.md)을 재사용한다.

## 구성과 선택 범위

브라우저 → 로컬 HTTP 조회 → `EvidenceReader` → PostgreSQL로 이어진다. Trace는 서버 시작 시 기존 OpenTelemetry(OTel) 로깅 파일을 읽고 허용 항목만 메모리에 보관한다. 이번 화면 검증은 저장된 실행 기록을 재조회하며 대상 앱 요청을 새로 발생시키지 않았다.

Python 표준 HTTP 서버와 브라우저 기본 기능을 사용해 새 의존성을 추가하지 않았다. 기존 JJAM-TONG 프로토타입 HTML의 화면 구성·메뉴·스타일을 재사용하고 실제 DB 조회 기능을 연결했다. 같은 서버의 `/demo`에서는 기존 합성 데이터와 확대 수준별 그래프를 체험한다. 전체 제품의 프런트엔드 기술·운영 서버를 확정하는 선택은 아니다. 운영용 웹 프레임워크·그래프 라이브러리의 채택은 이후 표시량·접근성·성능·운영 요구를 비교해 결정한다.

## 사용자 흐름과 판정

| 시나리오 | 기대 결과 |
| --- | --- |
| 처음 열기 | 분석본을 직접 선택할 수 있으며, 임의로 최신 빌드를 선택하지 않는다. |
| 빌드 선택 | 저장소·revision·빌드·모듈·JAR 해시·분석 해시를 확인할 수 있다. |
| 메서드 검색 | `BoardController`처럼 클래스명부터 읽고, 상세에서 패키지·descriptor를 확인한다. 이름이 같은 메서드는 별도 항목이다. |
| 정적 후보 탐색 | 분석기를 구분하고 시작 메서드의 나가는 호출 후보를 표시한다. 실행된 흐름으로 표현하지 않는다. |
| 같은 빌드의 Trace 조회 | 수집된 실행 구간과 부모 관계, 시간·오류, 미해결 메서드 후보를 확인한다. |
| 다른 빌드로 전환 | 이전 실행을 새 그래프에 붙이지 않고 불일치를 표시한다. |
| 빠른 선택 전환 | 이전 요청의 늦은 응답이 새 빌드·분석기의 결과로 표시되지 않는다. |
| 결과 없음·DB 오류 | 이전 결과를 남기지 않고 현재 조회 상태와 재조회 방법을 설명한다. |
| 좁은 화면·큰 결과 | 컨트롤과 식별자를 읽을 수 있고 표시 상한·부분 결과 이유를 확인한다. |

UI(User Interface, 사용자가 조작하는 화면)와 QA(Quality Assurance, 품질 검증)는 기능 설계와 함께 검토한다. 앞으로도 사용자 질문·탐색 흐름·근거의 의미·오류 상태·크기별 정보량을 먼저 정하고, API 검증과 브라우저 검증을 각각 남긴다. 전체 가시성은 사실과 한계를 구분해 읽을 수 있을 때 평가한다.

## 첫 조회 화면의 검증 기록

Python 시험 88개가 통과했다. 새 화면 소비자 시험 19개와 기존 근거·저장·수집·Boot 회귀 시험 69개다. 실제 PostgreSQL을 포함해 정확한 분석본 선택, 버전 불일치, overload 후보 유지, 시간 정밀도, 이전 이력 보존과 HTTP 조회 경계를 확인했다. HTTP 동시 처리 슬롯을 모두 사용하면 503을 반환하고 슬롯 반환 후 조회가 회복되는 것도 시험했다.

브라우저에서는 실제 DB·고정된 실제 Trace를 사용했다. WALA의 `BoardController.create`에서 메서드 13개·호출 근거 16개, JavaParser에서 7개·7개를 확인했다. 같은 빌드의 Trace는 `PARTIAL`이며 span 10개 중 메서드 정보가 있는 7개와 미해결 overload 3개를 표시했다. 다른 실제 빌드로 전환하면 span 10개를 거부하고 메서드를 연결하지 않았다.

빠른 빌드·분석기 전환에는 이전 응답을 지연시켜 결과가 섞이지 않는지 확인했다. HTTP 503과 시작 메서드가 없는 응답은 브라우저의 응답 경계에 주입해 화면 처리를 확인했다. 실제 DB 중단이나 새로운 앱 실행을 주입한 시험은 아니다. 상호작용과 크기별 표시의 상세 판정은 [구조화한 QA 기록](local-evidence-workspace-qa.json)에 남긴다.

브라우저 상호작용 19개가 통과했다. 너비 1440·1024·390px에서 가로 넘침이 없고 시작 메서드의 글자가 읽을 수 있는 배율로 유지되는지 확인했다. 스크린샷을 직접 확인했으며 브라우저 콘솔 기록은 0건이었다. 전체 그래프를 축소해서 볼 때는 이름을 줄이고, 시작점 보기·확대·드래그로 메서드를 읽도록 구성했다.

독립 코드 검토에서 저장된 자유 형식 진단 설명의 노출과 잘못된 시간값 처리를 지적받아 수정하고 회귀 시험을 추가했다. 재검에서 두 지적의 해소와 남은 구체적 결함 0건을 확인했다. 별도의 프런트엔드 정적 검토도 구체적 결함 0건이었다. AI 국문 편집 검토의 용어 설명·Trace 저장 위치·실행 기록 표현을 수정한 뒤 재검에서 남은 지적 0건을 확인했다.

## 기존 HTML 재사용과 추가 검증

기존 확대 수준별 그래프 시안의 HTML을 기준으로 밝은 콘텐츠 화면·어두운 왼쪽 메뉴·서비스 분석 흐름을 재사용했다. 원본의 스타일과 데모 동작을 `prototype.css`·`prototype.js`로 옮겼으며, 실제 조회 화면은 같은 스타일과 메뉴 안에서 기존 조회 API를 사용한다. 빌드를 고르면 선택 영역이 접혀 그래프에 공간을 내주고, `변경`으로 다시 열 수 있다. 메뉴를 옮겼다가 돌아와도 선택한 분석본과 그래프를 유지한다.

실제 조회 화면은 합성 데이터를 정의한 스크립트를 읽지 않는다. 인프라·자산·보안 등 연결 전 영역에는 수치를 채우지 않고 연결 상태를 표시한다. `/demo`는 기존 전사 시안을 제공하며 고정된 합성 데이터 안내와 실제 조회 화면으로 돌아오는 링크를 유지한다. 데모에는 실제 조회 스크립트가 없고 네트워크 연결도 브라우저 정책으로 차단한다.

재사용 뒤 Python 시험은 89개가 통과했다. 화면의 계약 시험 20개와 기존 회귀 시험 69개이며 실제 PostgreSQL을 포함한다. 실제 조회의 브라우저 시나리오 19개를 다시 실행하고, 메뉴 이동·선택 보존·빌드 선택 영역·시간 막대의 위치, 데모의 메뉴·확대 수준·키보드 이동을 추가로 확인했다. 너비 1440·1024·390px의 실제 화면과 모바일 데모에서 가로 넘침이 없었다. 상세 수치와 판정은 [HTML 재사용 QA 기록](local-platform-reuse-qa.json)에 남긴다.

## 해석할 때의 조건

첫 대상은 로컬의 `playground-boot-local` 조직 라벨이다. `boot-local-b1-r2`와 `boot-local-b2-r2`는 중첩 타입 식별자 오류를 수정한 분석본이며 이전 분석 ID도 이력으로 보존한다. 저장된 정상 등록 요청은 span 10개 중 메서드 정보가 있는 기록이 7개다. `validate`는 두 descriptor 중 어느 것을 실행했는지 미해결이며 외부 부모가 수집되지 않아 Trace는 `PARTIAL`이다.

현재 화면은 단일 로컬 사용자의 한정된 조회 도구다. 기업 인증·인가, Trace 지속 저장·수집, Boot의 CI 발행, 실시간 화면 갱신, 전체 MSA의 비동기 연결과 대형 그래프의 수용량은 앞으로 검증한다. [재현 명령과 조회 상한](../../tools/evidence_web/README.md)을 함께 읽는다.
