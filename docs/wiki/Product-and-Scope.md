# 제품 비전과 전체 범위

[위키 홈](Home.md) · 원본: [비전](../VISION.md), [프로젝트 정의](../PROJECT.md)

## 왜 만드는가

관계 그래프를 사람이 계속 고치거나 에이전트가 분석할 때마다 원본을 다시 모으면 버전·출처·시점이 어긋나기 쉽다. JJAM-TONG은 관계를 자동으로 발견·등록하고 변경에 맞춰 갱신하는 것을 목표로 한다. 이를 통해 **어떤 코드·배포의 어느 시점에서 무엇을 확인했는지** 근거를 조회할 수 있게 한다. 주요 사용자는 문제를 조사하는 에이전트와 서비스의 신뢰성을 관리하는 SRE 담당자다.

대표 질문은 “게시글 조회가 배포 후 느려졌는데, 어떤 실행·코드·배포·자산·보안 근거를 확인할 수 있는가?”다. 시간적 연관성을 원인으로 확정하지 않고 관측 사실·정적 후보·분석 가설·부족한 근거를 구분한다.

## 전체 구현 범위

| 영역 | 만들려는 사용자 결과 | 연결된 요구사항 |
| --- | --- | --- |
| 코드 관측성 | 호출 가능 관계와 실제 요청 실행을 같은 코드·빌드 버전에서 탐색 | [E01 #2](https://github.com/DDINGJOO/JJAM-TONG/issues/2) |
| 자동화·에이전트 | GitHub 기반 발견·등록, 변경 추적, 출처와 한계를 가진 기계 조회 | [E02 #9](https://github.com/DDINGJOO/JJAM-TONG/issues/9) |
| SRE·MSA·인프라 | 지연·오류와 서비스·배포·워크로드·자원을 연결 | [E03 #16](https://github.com/DDINGJOO/JJAM-TONG/issues/16) |
| 카탈로그·구성 관리 데이터베이스(CMDB)·보안 정보 및 이벤트 관리(SIEM) | 논리 서비스, 자산·소유권·이력, 관련 보안 근거를 연결 | [E04 #23](https://github.com/DDINGJOO/JJAM-TONG/issues/23) |

위 영역은 **모두 구현 대상**이다. 구현 순서는 의존성과 비교 실험으로 정하며 현재 지원 완료를 의미하지 않는다. 모노레포에서 영역·연동 경계를 두고 시작하는 방향이며 실제 모듈 계약·실행 배치·분리 시점은 토론한다.

## 환경과 이식성

첫 개발 목표는 **별도 프로젝트에 도입할 코드 관측성 라이브러리와 필요한 연동 도구**다. 대상 앱 소스는 별도 저장소에 유지하고, 초기 연동·통합 검증은 로컬에서 수행한다. 플랫폼 내부에는 정확성 검증용 작은 합성 테스트 코드를 둘 수 있다. 적용 형태·후보 선택과 미검증 범위는 [첫 개발 단계](../PROJECT.md#첫-개발-단계-외부-프로젝트에-도입할-라이브러리)와 [T25 #44](https://github.com/DDINGJOO/JJAM-TONG/issues/44)에서 확인한다.

관측 지원 대상은 AWS EKS·ECS와 일반 Kubernetes, 카탈로그 매핑 대상은 온프레미스·AWS 자원이다. **플랫폼을 어디에 설치할지와 관측 대상이 어디서 실행되는지는 별도 선택**이다. 이름만으로 서비스를 자원에 붙이지 않고 공급원·식별자·환경·유효 시간·출처·충돌을 보존하는 행동을 검토한다.

지원 언어·런타임·CI·수집 도구별 기능 수준은 따로 검증한다. 특정 클라우드나 언어의 식별자를 모든 환경의 필수 조건으로 확정하지 않는다. 세부 반례는 [이식성과 자원 매핑 명세](../requirements/README.md)에 있다.

## 현재 확인 수준

요구사항과 로컬 비교 실험이 있으며 운영용 메서드 분석기·계측·통합 조회 제품은 아직 없다. Python/SQLite 실험은 제품 기술 채택이 아니다. 블로그 작성·발행은 이 프로젝트의 목표에 포함하지 않는다. 실제 구현·미검증의 구분은 [실험 페이지](Research-and-Experiments.md)에서 확인한다.

## 첫 라이브러리 구현

[빌드 식별 계약 라이브러리](../../libraries/evidence-contract-java/README.md)는 외부 의존성 없는 Java JAR로 만들었다. JDK 17·21에서 각 23개 계약 검증을 통과했으며, JDK 17 JAR을 JDK 21 소비자가 사용하는 검증도 통과했다. [ADR 0002](../decisions/0002-experimental-build-identity.md)와 [실행 기록](../experiments/library-contract-results.json)에 범위와 조건을 남긴다. 메타데이터의 일치를 확인하는 공통부이며 자동 메서드 분석·실행 수집 완료를 뜻하지 않는다. 사용자 요청에 따라 실제 Kafka·Redis·PostgreSQL을 쓰는 합성 MSA 대상도 별도 로컬 저장소에 만들었다. [외부 앱 적용·장애 복구 9개 시나리오와 실행 한계](../experiments/LOCAL-MSA-TARGET.md)를 확인할 수 있다.
